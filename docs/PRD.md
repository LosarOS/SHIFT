# SHIFT — product brief / PRD

## Vision

Один понятный жест возвращает пользователя в рабочий контекст. SHIFT снимает повторяющуюся подготовку рабочего места, сохраняя контроль за каждым запуском. Продукт local-first и privacy-first, работает без сети за исключением явно открываемых пользователем сайтов и приложений.

## Проблема и позиционирование

Пользователь каждый день открывает одинаковые инструменты, папки и ссылки. Ярлыки и скрипты позволяют часть автоматизации, но затрудняют редактирование, контроль ошибок и разделение контекстов. SHIFT объединяет видимый сценарий запуска, историю и комфортный Windows UX.

Сильная сторона — предсказуемость, локальное хранение и низкое трение. Обещание MVP: «собрать и запустить инструменты задачи». «Полностью восстановить состояние любых приложений» в MVP не обещается: Windows не предоставляет единого такого API.

## Personas

| Persona | Задача | Боль | Критерий пользы |
|---|---|---|---|
| Разработчик / интегратор ELMA365 | IDE, Postman, папка, несколько страниц документации | Переключение проектов с разными ссылками | Создать второй контекст и запустить без ручного поиска |
| Аналитик / специалист | Браузер, документы, мессенджер | Повторяющаяся подготовка утра | Открыть нужные материалы одним действием |
| Студент | PDF, заметки, Word и LMS | Материалы разбросаны по папкам | Вернуться к учебной теме через неделю |
| Стример | OBS, Discord, музыка, dashboard | Важно не забыть инструмент и порядок | Видеть, что запуск состоялся, и исправить ошибку |

## Основной сценарий

1. Первый запуск объясняет границы продукта; пользователь создаёт демо или начинает с пустого списка.
2. Создаёт пространство, задаёт название, описание, теги и цвет.
3. Добавляет локальное приложение / ярлык, документ, папку, URL или явную команду.
4. Меняет порядок, задержки и включённость. Сохраняет.
5. Запускает с карточки или деталей. Для команд видит полный текст и оболочку и подтверждает.
6. Следит за очередью. Ошибка элемента сохраняется, остальные продолжаются. Может отменить оставшиеся шаги.
7. Позже видит результат в истории, изменяет или копирует пространство.

## Scope и acceptance criteria

| Возможность | Критерий |
|---|---|
| CRUD / clone | Сохраняются после перезапуска; копия получает новые workspace/item IDs |
| Теги / favorites / поиск | Поиск по имени, описанию и тегам; избранное отдельно; реальные данные из SQLite |
| Элементы | Все 5 типов; только App получает отдельные arguments; у команды текст включает параметры |
| Порядок / задержка | Строго последовательно, задержка перед элементом; 0–300000 мс |
| Статусы | Pending, Running, Success, Failed, Skipped; финальный статус очереди |
| Отмена | Оставшиеся skipped, уже переданные ОС success; процессы не завершаются |
| Ошибки | Нет обрушения всей очереди из-за одного пути; сообщение в UI и durable history |
| Команды | Запрет скрытого запуска; подтверждение каждый раз; пользовательские права, без elevation |
| Import/export | Versioned JSON, проверка размера и схемы, preview, новые IDs, импорт не запускается |
| Backup | SQLite online backup; atomic export; ручное восстановление описано |
| UX | 5 разделов, onboarding, пустые состояния, доступные подписи; RU/EN, 4 темы |
| Windows | Трей, явный выход, текущий пользователь Run key; portable без автозапуска |

Ограничения: максимум 100 элементов / workspace, 20 тегов, 2 MB JSON. Запуск одной очереди на экземпляр / каталог данных. В MVP нет параллельного режима: последовательный сценарий даёт точную семантику задержек и отмены.

## Метрики успеха

Без отправки телеметрии. Для добровольного пользовательского теста: время до первого сохранённого пространства, доля повторного использования через неделю, понятность ошибок и отмены. Цели beta: собрать 5 инструментов за 3 минуты; начать повторный запуск за 2 действия или меньше. Эти значения — цели, не измеренные результаты.

## Non-functional

- Windows 10 build 19041+ / Windows 11 x64; основной UX — Windows 11.
- Данные локальны, нет обязательных API, сетевых аккаунтов и фоновых внешних запросов SHIFT.
- Запуск без администратора; shared/UNC paths и системные device paths не поддерживаются в MVP.
- Локальные diagnostic logs с ограничением объёма; transactions, version guard и crash recovery.
- Клавиатурная навигация и подписи; high contrast и Narrator требуют ручного release gate.
- Цели beta: старт UI <2 с на обычном SSD, рабочее множество <200 MB для 100 пространств. Ещё не измерено.

## Release policy

0.1.0 — engineering preview. До public beta обязательны Windows CI, ручная QA-матрица и воспроизводимая установка/удаление. SmartScreen для unsigned сборок ожидаем; публичному релизу нужен план подписи. Не называть release-ready только на основании тестов ядра.
