# SHIFT — product strategy / 2026

Дата discovery: 2026-11-14. Исходный main: `205a5ff421f6084c7714f794e505e0d5e59b5afb`, опубликованная версия RC7. Это план и source review, не подтверждение выпуска RC8.

## Аудитория и проблема

Разработчики, аналитики, студенты и стримеры заново собирают один и тот же набор программ, документов и ссылок. Им нужен быстрый переход к контексту с понятными действиями, ошибками и восстановлением, без обязательного облака.

Сильные стороны: local-first SQLite, native Windows UI, явный command consent, Workspace Doctor, Composer/Plan, reversible Studio, installer/portable и сохранённые доказательства CI. Ограничения: последовательный dispatch не означает готовность приложений; произвольный session/window capture отсутствует; физическая Windows/DPI/accessibility матрица не закрыта. Backup SQLite не включает все внешние ресурсы.

## Сценарии

1. Development: выбрать сохранённое пространство → проверить цели → увидеть порядок → подтвердить команды → запустить; при ошибке понять, какие шаги пропущены.
2. Study/Focus: открыть документы и заметки → явно применить спокойный Studio-профиль → управлять таймером; выключить Studio без удаления конфигурации.
3. Streaming: отдельный набор приложений и быстрых действий; никаких скрытых установок или команд в импортированном оформлении.
4. Recovery: найти SQLite-копию → проверить приватный снимок → изучить состав → подтвердить restore с safety-копией. Для полной копии ресурсов отдельно Quit и копирование всего каталога.

## Ориентиры качества

[PowerToys Workspaces](https://learn.microsoft.com/en-us/windows/powertoys/workspaces) — ориентир для ясного запуска контекста и честных ограничений восстановления окон. SHIFT выделяется связкой read-only диагностики, управляемого запуска и обратимого оформления Studio, а не обещанием универсального управления любой программой.

## Согласованный ближайший scope

1. **Сценарии запуска:** сохранённая opt-in предварительная проверка и политики continue/stop/skip с сохранением command consent, последовательности и отмены. Никаких неявных retries.
2. **Quick Actions:** пятый управляемый native widget, до12 декларативных действий. Пространства разрешаются из актуального store; другие цели проходят обычную validation/launch цепочку. Предпросмотр не исполняет действия.
3. **Recovery Center:** инвентаризация, приватная проверка SQLite, состав данных и существующий безопасный restore. **Полный ресурсный архив не входит в реализованный срез**: UI должен явно объяснять отдельное копирование Images/RecoveryNotes после Quit.

Общий UX: RU/EN, существующие темы, доступные controls, понятные пустые/ошибочные состояния. GitHub: русский основной README, English, честные скриншоты, ссылки на опубликованные сборки и оригинальные SVG-иллюстрации.

## Риски и границы

- Новый WidgetKind требует совместимости SQLite CHECK и JSON: schema3 с предварительным backup, транзакционной миграцией и отказом старого приложения открывать будущую схему. Обратный переход — через сохранённую старую копию.
- Quick Actions — не sandbox. Даже разрешённый документ открывается системным обработчиком. Ссылки не проверяются скрыто по сети. Никаких полей произвольного shell в новом типе.
- Profile pack не является full backup; локальные Actions исключаются из profile-pack и настраиваются заново. Single-widget декларации имеют отдельные правила: импорт не создаёт окно и не исполняет действия.
- Snapshot preflight не гарантирует, что файл не удалён после проверки; dispatch обязан сохранить обычную обработку ошибок.
- Windows Server automation не закрывает физическую Win10/11, DPI100/125/150/200%, mixed monitors, Narrator/high contrast, sleep/RDP и fullscreen.

## Acceptance / evidence

До объявления кандидата проверенными: core regressions; backward settings; schema2→3 backup/migration и restore; invalid/corrupt input; no launch from preview/import; command refusal; cancellation; lifecycle; RU/EN; настоящий native publish/resources; portable/installed preservation. Полные результаты ведёт root в отчёте инженерной сессии, а не этот план.

Публикация — только после quality gates и отдельного подтверждения владельца. Stable1.0, подпись, отсутствие SmartScreen и неподтверждённая производительность не обещаются.

## Следующие шаги

Закрыть forced conflict/live GUI и физическую матрицу; собрать обратную связь по новому сценарию; затем исследовать bounded parallel launch, process-aware behavior и window-layout capture как самостоятельные модули. Не добавлять Explorer injection/WorkerW, скрытую отправку данных или elevated changes.
